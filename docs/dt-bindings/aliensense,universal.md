# aliensense,universal — the universal sensor node

The universal driver serves any sensor head behind an Aliensense GMSL pod. The
device tree tells it three things: the register map's widths, the capture
modes (the standard tegracam `modeN` children, generated by `nxs host overlay`),
and a control table per sensor that lets the driver implement the tegracam
control callbacks without knowing the sensor by name. The register programs that bring a sensor
up never live here; the NXS unit on the pod runs them.

## Node

```
universal_cam1_a: universal_cam1@1a {
    compatible = "aliensense,universal";
    reg = <0x1a>;
    aliensense,reg-bits = <16>;
    aliensense,val-bits = <8>;
    ...
    mode0 { aliensense_sensors_pool = "framos,imx900;"; ... };
    mode1 { aliensense_sensors_pool = "framos,imx335;"; ... };

    aliensense-ctrl {
        ctrl@0 {
            aliensense,sensor  = "framos,imx900";
            aliensense,inck-hz = <74250000>;
            aliensense,ctrl-group-hold   = <0x30F8 1 0 1 1 0 0 0>;
            aliensense,ctrl-gain         = <0x3514 2 0 1 1 1 480 0>;
            aliensense,ctrl-exposure     = <0x3240 3 0 1 1550 85 1 0>;
            aliensense,ctrl-frame-length = <0x30D4 3 0 1 0 0 0 0>;
            aliensense,ctrl-line-length  = <0x30D8 2 0 0 0 0 0 0>;
            aliensense,ctrl-standby      = <0x3000 1 0 0 1 0 0 0>;
            aliensense,ctrl-start        = <0x3010 1 0 0 0 0 0 0>;
            aliensense,ctrl-trigger      = <0x3400 1 0 0 0x00 0x0A 0x09 0>;
            aliensense,ctrl-vint-en      = <0x323E 1 0 0 0x1A 0x18 0x19 0>;
            aliensense,ctrl-sync-sel     = <0x343C 1 0 0 0xC0 0xF0 0 0>;
            aliensense,ctrl-test-pattern = <0x3550 1 0 0 0x06 0x07 0x3551 0>;
            aliensense,ctrl-black-level  = <0x35B4 2 0 0 0 0 0 0>;
        };
    };
};
```

## Properties

The node's `reg` is the sensor's I²C address. `aliensense,reg-bits` (8 or 16,
default 16) and `aliensense,val-bits` (8 or 16, default 8) size the register
map; both come from the personality's I²C profile. A control's `width` counts
bytes, so on a 16-bit-value part a 2-byte control is one register and a
4-byte control two.

Each `modeN` child carries the standard tegracam properties plus
`aliensense_sensors_pool`, the sensor compatible followed by `;`. The driver
matches it against `aliensense,sensor` of the `aliensense-ctrl` children to
pick the control table for the selected mode.

`aliensense-ctrl` holds one `ctrl@N` child per sensor the node may serve
(at most 4). Its properties:

| Property | Type | Meaning |
|---|---|---|
| `aliensense,sensor` | string | Sensor compatible, matched against the mode's pool tag |
| `aliensense,inck-hz` | u32 | Sensor input clock; line time = line-length / inck |
| `aliensense,ctrl-<name>` | 8 × u32 | One control: `addr width order form p0 p1 p2 p3` |

Cells common to every control: `addr` is the register address of the first
slot, `width` the byte count (1 to 4), `order` 0 for little-endian and
1 for big-endian slot placement, `form` selects the formula, `p0..p3` are
its parameters. A control the sensor lacks is left out; the driver then
reports the matching V4L2 control as unsupported and leaves the register
alone.

| Control | Form | Parameters | What the driver writes |
|---|---|---|---|
| `group-hold` | 1 | p0 hold value, p1 release value | p0 when the framework opens a group hold, p1 when it closes it |
| `gain` | 1 | p0 numerator, p1 denominator, p2 max | `reg = clamp(val * p0 / p1, 0, p2)`, `val` in the mode's `gain_factor` units (dB × factor) |
| `exposure` | 1 | p0 integration offset ns, p1 register floor, p2 minimum lines | Sony inverted shutter: `lines = (t − p0) / line_time`, `reg = frame_length − lines`, clamped to `[p1, frame_length − p2]`; `t` from the mode's `exposure_factor`. Ignored while `shutter_mode` is fast trigger, where the XTRIG pulse width is the exposure |
| `frame-length` | 1 | p0 minimum rows above the active height | `reg = inck × framerate_factor / (line_length × val)`, floored at `active_h + p0`; the register the exposure law reads back |
| `line-length` | 0 | – | Read once per `set_mode`; the HMAX the laws divide by |
| `standby` | 0 | p0 standby value, p1 run value | Reserved for the host tool; the driver reads the layout only |
| `start` | 0 | p0 start value | Reserved for the host tool |
| `trigger` | 0 | p0 normal, p1 fast trigger, p2 sequential | Values behind the `shutter_mode` control; the driver records the mode, the host tool programs the conversion |
| `vint-en` | 0 | p0 normal, p1 fast, p2 sequential | Companion of `trigger` |
| `sync-sel` | 0 | p0 master, p1 slave | Written by the `operation_mode` control |
| `test-pattern` | 0 | p0 off value, p1 on value, p2 select register | `test_pattern = 0` writes p0; `N` writes `N` to p2 then p1 |
| `black-level` | 0 | – | Raw value, `width`/`order` placement |

## V4L2 controls

The standard tegracam controls (`gain`, `exposure`, `frame_rate`,
`group_hold`, `sensor_mode_id`) act through the table. The driver adds four
private controls named after the FRAMOS Jetson drivers so their tooling
habits carry over:

| Control | Values | Effect |
|---|---|---|
| `operation_mode` | 0 master, 1 slave | writes `sync-sel` |
| `shutter_mode` | 0 normal, 1 sequential trigger, 2 fast trigger | records the mode the host tool configured; under fast trigger `exposure` is not written |
| `test_pattern` | 0 off, N pattern code | writes `test-pattern` |
| `black_level` | integer | writes `black-level` |

Writes made while the pod is not brought up (before `nxs <port> on`) fail on
the bus; during probe they are logged and ignored so the node still
registers, afterwards they return the bus error to the caller.

## Limits

A control spans 1 to 4 bytes; one formula family per control; the exposure law
needs the live line length and frame length, which the driver reads at
`set_mode` and caches from `set_frame_rate`. The trigger conversion itself
(standby, trigger registers, the deserializer's generator ordering) is the
host tool's, never the kernel's.
